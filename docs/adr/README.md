# 架构决策记录（ADR）

本目录记录**已经拍板、并且会影响后续取舍**的技术决策。与 `GLOSSARY.md` 分工：术语表定义「我们怎么称呼这件事」，ADR 记录「为什么这么做、当时否掉了什么」。

## 什么时候写

- 在两个方案之间做了取舍，且理由不是显然的
- 这个决定会被后来的代码持续引用（改它需要改动多处）
- 有人会问「为什么不直接用 X」

## 什么时候不写

- 只是实现细节，改名或抽象就能变
- 决定已经被代码完全表达，无需额外解释
- 纯领域术语 → 写进 `GLOSSARY.md`

## 格式

文件名 `NNNN-短横线小写标题.md`，正文包含：

- **状态**：已采纳 / 已取代（指向取代它的编号）
- **日期** 与 **来源**（原始文档链接或 commit）
- **决策**：一句话说清选了什么
- **背景**：当时面对什么问题
- **理由**：为什么选它
- **替代方案**：否掉了什么，为什么

## 写法约定

ADR 是历史记录，不是现状描述。事实变化时**新增**一条 ADR 并把旧的标为「已取代」，不改写旧的论证——当时的信息不全，改写会抹掉这个事实。
