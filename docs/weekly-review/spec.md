# 周末总结 Spec（周一至周日整周）

## 背景
当前 App 会记录通过 App 创建的学习日程，但用户需要手动从历史记录中回顾一周学习内容。新增“周末总结”栏目，集中呈现本周主动添加的学习内容，并支持复习标记与总结笔记。

## 目标
- 让用户按周查看本 App 新增的学习内容。
- 将复习计划与单次日程区分展示，但不重复列出自动生成的复习提醒。
- 支持用户记录每周总结并标记已复习内容。
- 保留历史周数据，便于长期回顾。

## 功能需求
- F1: 主界面提供“周末总结”入口，打开独立总结页面；此处的“周末总结”特指周一至周日整周的学习回顾，并非仅覆盖周六、周日两天。
- F2: 总结页面按周一至周日划分周次，默认显示当前周，并展示该周日期范围。
- F3: 页面只列出本 App 创建且创建时间落在所选周内的学习条目；每个创建动作只展示一次，不因后续复习日期重复展示；其他来源的系统日历事件不展示。
- F4: 每条学习条目展示标题、“基准学习日期”和日程类型（复习计划或单次日程），并按创建日期分组。“基准学习日期”指用户在创建该日程时所选择的那个起始日期（即首次学习的日期），与 App 中的“创建时间”不同；复习计划产生的多个复习日期不作为基准学习日期重复展示。
- F5: 总结页面提供“上一周”和“下一周”两个按钮用于在周次之间切换（向前可翻至历史周，向后可回到当前周；位于当前周时“下一周”按钮禁用）；没有条目时展示明确空状态，文案固定为“本周还没有学习条目，去主界面添加吧”。
- F6: 每条学习条目的左侧都有一个独立的勾选框（Checkbox）；用户点击该勾选框可在“已复习”与“未复习”之间切换，再次点击取消勾选。勾选框状态独立于条目本身，页面顶部展示该周“已复习 X/Y”的进度，X 与 Y 在切换时即时刷新。
- F7: 用户可以编辑每周总结笔记；每次编辑（输入、删除任意字符）立即写入本地，无需手动点击“保存”按钮。笔记按周独立存储，切换周次或关闭后重新打开仍能恢复原文。
- F8: 学习条目、复习状态和总结笔记永久保存在本地，独立于现有最多 20 条的历史记录限制，不自动删除。
- F9: 现有历史记录功能继续工作；已有历史数据可正常读取。旧数据若缺少“日程类型”（Type）字段一律按“复习计划”兼容展示，其已有的复习勾选状态按现有规则继续计入。
- F10: 通过本 App 在**周六或周日**创建的**复习计划**，在创建所在周和下一周都作为 `WeeklyEntry` 双份显示：第二条 `creationDate` 改为下一周周一 `00:00:00`。
- F11: 周末复习计划的双份预占位条目，仅在第二条的 `creationDate` 落在下一周周一、且 `isPreOccupiedNextWeek = true`；UI 在其右侧加"上周周末创建"标签（`.secondary` 颜色），用以区分本周真实条目；副标题改为 `创建于 X · Y 所在周开始复习`，其中 `X = entry.creationDate` 的中文格式（= 下一周周一）、`Y = 该条目的归档周周一`（原创建所在周的周一 = 当前周一 - 7 天）。
- F12: 周末复习计划的双份规则**不**适用于单次日程（`.single`）以及周一至周五创建的复习计划。
- F13: 已存在的旧 `WeeklyEntry`（创建时间落在周六/日、`scheduleType == .review`、且尚未补预占位）由一次性迁移逻辑补一份下一周周一 00:00 的预占位副本；迁移幂等，由独立 key 保护。
- F14: 周末复习计划预占位条目（`isPreOccupiedNextWeek = true`）**不计入** 周内的 `totalCount` 与 `reviewedCount`；X / Y 只统计本周真实条目。即便勾选预占位条目，`reviewedCount` 仍以真实条目为准；该勾选状态通过 `reviewedIds` 与真实条目共享（同 id），便于跨周保持一致。

## 非功能需求
- N1: 遵循现有 macOS 14+、SwiftUI、EventKit 和中文本地化约定。
- N2: 周次计算使用系统当前时区；周一为一周第一天，日期边界按本地时间计算。
- N3: 周末总结不新增网络请求，数据仅保存在本机。
- N4: 现有创建、撤销、日历权限和窗口设置功能的行为不改变。

## 不做的事
- 不统计系统日历中由其他 App 或用户手动创建的事件。
- 不把自动生成的复习提醒作为新的学习条目重复统计。
- 不提供 AI 自动生成总结、云端同步、导出分享或复杂掌握度评分。
- 不自动清理旧周数据。
- 不改变现有历史记录最多 20 条的规则。
- 不放宽“下一周”按钮的禁用规则为预占位条目服务（F5 规则原样保留）；预占位条目对用户而言仍位于下一周，UI 通过"上周周末创建"标签显式标注。
- 不把预占位条目计入 `totalCount` / `reviewedCount`（F14 规则原样保留）；勾选预占位条目不影响 X / Y 显示。

## 验收标准
- AC1: 打开主界面可看到“周末总结”入口，点击后出现独立总结页面。
- AC2: 当前周页面显示周一至周日的日期范围，且周切换后范围和内容同步变化。
- AC3: 创建一条复习计划和一条单次日程后，在其创建所在周各显示一条；后续复习日期不会产生重复条目，系统其他来源事件不出现。
- AC4: 每条条目可观察到标题、首次学习日期、类型和按创建日期的分组。
- AC5: 点击条目复习勾选框后，已复习进度立即更新；关闭并重新打开页面后状态保持。
- AC6: 输入每周总结并切换周次后，返回该周时原笔记仍存在；历史周可查看。
- AC7: 没有本周条目时页面显示空状态，而不是空白区域或错误。
- AC8: 既有历史记录仍可打开、选择和删除；已有数据不会因新增类型字段而无法读取。
- AC9: 构建和单元测试通过，且现有日程创建、撤销和权限流程的测试或手工回归不受影响。
- AC10: 现有历史记录达到 20 条上限被截断时，周末总结中已存在的学习条目、复习勾选状态和该周总结笔记仍完整保留，不受 20 条上限影响。
- AC11: 切换到任意历史周都能查看该周的条目、复习勾选和总结笔记，相关数据长期保留且不会被自动清理。
- AC12: 在周六创建一条复习计划后，`weeklyEntriesData` 出现两条：一条 `creationDate` 等于创建时的周六，一条 `creationDate` 等于下一周周一 00:00 且 `isPreOccupiedNextWeek = true`；两条 `id` 相同。
- AC13: 在周日创建复习计划同样双份；单次日程以及周一至周五创建的复习计划不双份。
- AC14: UI 在预占位条目右侧显示"上周周末创建"标签（`.secondary` 颜色）；副标题显示 `创建于 X · Y 所在周开始复习`（X = 预占位条目 creationDate 中文格式，Y = 归档周周一中文格式）；勾选、笔记行为不变（基于 `id` 仍能勾选/取消，笔记按周独立）。
- AC15: 已存在但未补预占位的旧 `WeeklyEntry`（创建时间周六/日 + `.review`）由一次性迁移补一份下一周周一 00:00 的预占位副本；迁移幂等，重复构造 VM 不会重复补。
- AC16: 在创建所在周（周六所在周）页面，`totalCount` 只统计真实条目（不含预占位条目），即便勾选预占位条目 `reviewedCount` 仍以真实条目为准；下周页面（仅含预占位条目）`totalCount` = 0，预占位条目仍可见但不计入 X / Y。
